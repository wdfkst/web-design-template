# 后台风格库接入设计

状态：设计草案，待独立检查与用户审阅；不是实施授权。日期：2026-11-02。

## 已确认目标

首批五套：soft 柔和立体、warm 温润自然、mist 雾色微光、porcelain 光瓷科技、aurora 极光空间。用户已经看过并确认这五个方向。平台应先展示可比较的风格，再按选择与业务需求生成后台；布局、插画、元素、配色、卡片和按钮均应有区别，不只是换色。范围仅后台，不包含官网。

已有视觉原型在 `.vudt/style-preview-gen/preview-r3/content/coffee-tech-r3.html`。它是视觉参照，不是正式模板。soft/warm/mist 有真实 AI 示例图片；porcelain/aurora 为明确标注的临时示意，不能称为 AI 成图。当前不新增付费调用。

以下技术细节均为助手建议，非用户逐项指定。

## 用户流程

创建任务入口增加可选的“后台风格”区。未启用时沿用现有自由生成流程；启用后明确表示生成后台管理系统，必须选择五套之一，不悄悄预选。风格卡片展示名称、特点和工作台缩略图；详情可切换同一咖啡业务的工作台、订单列表、商品编辑三个页面。

提交时传 description 和可选 adminStyleId。任务详情展示风格名称和版本。预览加载失败提供明确错误和重试按钮，不影响返回选择器。仅浏览/切换风格不调用模型。

## 数据契约与快照

定义 AdminStyleId 为上述五个固定字符串。POST /tasks 中 adminStyleId 缺省保留原行为；出现时必须是合法字符串，null、空串、未知值或其他类型返回 400，禁止静默忽略。客户端不提交任意 CSS、风格版本或材质提示词。

服务端从受信任注册表解析不可变 `{id, version: 1}` 引用，记录在任务的可选 adminStyle 字段中，随 TaskView 返回，并传入 drafting 和最终 spec。注册表以 id+version 查找，已发布 v1 定义不得原地修改；升级添加新版本。只有风格引用、主题和已解析表现数据进入 spec，不带服务端配置或凭证。

重试保留原风格引用，不重新挑选最新版本；其他模型设置仍遵循现有重试语义，不借此重构。未知历史版本在任何模型调用前明确失败，不降级成当前版本。缺省旧任务不注入新字段或改变旧默认。保留当前内存任务索引边界，不新增重启恢复或持久化系统。

选择风格即显式要求 admin；模型返回非 admin 时进入现有校验反馈重试，不默默忽略用户风格，不将不兼容页面强行改成后台。没有风格的营销项目保持原路径。

## 确定性应用位置

当前 `server/src/spec-source.ts` draftSpec 在取得 unknown 后调用 deriveSpecInput，再 parseProjectSpecInput，最后 finalizeSpec。新约束放在服务端共享编排层、derive 之前，而不是只在某个 OpenAI provider 内覆盖。

drafter 接收受信任风格引用和简短约束，用于规划业务模块及插画主题。取得输出后，先确认基本对象形状和 admin 类型；只替换受风格控制的主题、表现、插画风格字段，不能修复或掩盖业务结构错误。异常原文、坏 JSON 和结构错误保持现有反馈路径。模型不得覆盖用户选择。

应用后仍经过 derive、schema 校验与 finalize；资产几何只由现有侧车决定，风格不得写宽高。风格程序不任意增删表单、collection、导航或业务路由。测试替身、其他 provider 也必须经过同一约束步骤。

## 风格定义与布局

风格是独立于旧 appearance 的概念，不把五个 ID 塞进 decoration。旧 plain/soft-glass/jelly 路径保持原意。新模板通过受信任风格配置选择壳、工作台布局变体与组件皮肤，共享业务组件，不复制五套业务逻辑。

- soft：图标侧栏、欢迎主区加项目卡片网格；软质立体素材、大圆角浮起卡片、胶囊按钮。
- warm：展开侧栏、宽主内容区及日程/便签辅助区；米白/陶土/鼠尾草绿，自然纸感插画、低阴影中圆角。
- mist：顶部导航、分区工作台；轻透辅助面板，数据与表单实底；磨砂半透明插画、低饱和柔光。
- porcelain：宽侧导航、错落主次模块；白/冰蓝/银、厚实圆角实体卡、精密分隔、陶瓷与磨砂金属素材。
- aurora：顶部导航、主工作区加右侧上下文；深靛蓝与紫青柔光、分层实底面板、光学材质，禁止满屏霓虹。

布局差异必须有不同 DOM 区域与顺序/模块分配，不能仅改变 gap、卡宽或 CSS 变量。缺少日程等业务数据时用合理的已存在业务模块填充或移除辅助区，不能虚构业务实体。移动端按任务顺序折叠，禁用装饰导致的横向滚动。

每套涵盖表格、筛选、分页、表单、校验提示、按钮、空状态及登录页；登录页沿用已验证的登录/退出/守卫逻辑，只适配视觉，不能因新布局破坏无登录或仅登录项目。soft/warm/mist/porcelain 首批固定浅色，aurora 固定深色；命名风格不展示尚未设计的明暗切换，旧项目维持原切换能力。

颜色/圆角/组件令牌由版本化定义控制。用户业务描述不覆盖已选风格的受控视觉字段；若以后支持品牌色，作为另一个显式输入设计，不在本期隐式加入。

## 插画和缓存

保留现有 StyleBible 七种 artStyle，新增可选的受限材质字段 material：soft-clay、natural-paper、frosted-glass、porcelain-metal、aurora-optical。这比将材质冒充绘画风格更清晰。每套注册表固定材质及完整合法 StyleBible 参数；业务主题 prompt 仍来自需求，palette 仍由最终主题派生。

material 有值时构建受信任的正向材质描述，进入统一风格前缀，不放进 negativePrompt。将 material 纳入资产缓存键；缺省时必须保持旧资产哈希算法输入完全相同，避免旧缓存全部失效。材质或最终配色变化必须改变哈希；仅改不影响图片的布局参数不必使图片缓存失效。

维持原透明背景、构图、尺寸、处理器、预算与负面提示约束，不为每个卡片强制增加图片。示意素材明确标记，不能以科技风已有 AI 图片为验收前提。新增真实生成需另获授权。

## 正式预览与样例

使用单一确定性咖啡业务 fixture，包含合法工作台、订单列表、商品编辑及必要详情/路由依赖。由相同风格应用函数、codegen、vue3-admin 模板和构建链产出五个项目；无需 drafter 或付费 provider。fixture 图片是已批准本地素材或带明确说明的静态示意，非 API 密钥或远程用户图片。

正式风格目录记录 id/version 和静态预览地址。预览制品与平台一起构建发布；缺制品或版本不一致使校验失败，不能显示旧图冒充新版本。iframe 使用明确隔离策略和固定本地资源路径，禁止凭风格 ID 拼任意文件路径，不复用临时 companion 服务作为正式入口。

预览与用户产物共享组件/布局版本，但业务内容与主题图随需求改变，不承诺逐像素相同。所有业务数字标为示例，浏览预览不触发真实业务写操作。

## 验收

1. API：缺省兼容、五种合法 ID、非法输入 400、客户端伪造版本不生效；队列/权限逻辑不退化。
2. 编排：模型输出冲突主题被确定性覆盖，坏 JSON 不被掩盖，非 admin 反馈，所有重试保持选择；未知版本在付费调用前失败。
3. spec/图片：最终风格引用与受控字段一致、material prompt 正确、旧哈希不变、材质变化失效、侧车几何不变。
4. 导出：五套分别通过类型检查与构建；工作台/列表/编辑 15 个组合都可操作、布局差异有断言，不只检查 CSS 字符串。
5. 预览：版本一致，资源和图片加载成功，桌面1440和手机390无页面横向溢出，列表可在自身容器滚动。
6. 可访问性：正文对比度至少4.5:1、键盘焦点清楚、选择器和预览弹层可用键盘退出/返回；状态不只靠颜色；reduced-motion 禁用非必要动画。
7. 视觉：五套三页逐套检查；科技插画当前仍属示意的事实必须可见；保持现有登录守卫/退出、auth-only/no-auth回归。

## 非目标

官网风格、自定义任意 CSS、用户自行混搭材质、自动修复业务 schema、任务持久化、模型配置改动、自动付费图片重试、将当前原型直接复制成正式平台组件。

## 独立检查后的工程裁定

以下均由助手作工程选择，不要求用户决定代码组织：

1. 注册表使用类型化 TypeScript 常量，包含 id/version、名称、完整 theme、完整 presentation、插画参数（seed 除外）、shellVariant、workbenchLayout 和组件皮肤标识。程序控制 theme 全字段、experience.presentation 全字段、styleBible 除 seed 外全部字段及最终 adminStyle 引用；palette 由受控 theme 派生，seed 保留合法模型值或按项目生成一次稳定值。业务 pages/collections/forms/navigation、资产主题与 alt 不受风格覆盖。旧 appearance 仅作底层兼容映射，不能替代新布局标识。
2. 模板共用 AdminLayout 和业务组件，新增专用导航壳/工作台布局子组件；按 shellVariant/workbenchLayout 渲染实际区域。命名风格布局优先于旧 classic/focus 表现变体，但保留其业务数据；旧路径不改变。辅助区由模板对已有模块作确定性分配，无合适数据则隐藏，不让 LLM 发明日程。具体组件拆分与断言位置在实施计划中列明。
3. 五套同时固定 artStyle 与 material：soft=3d-clay/soft-clay，warm=hand-drawn/natural-paper，mist=isometric/frosted-glass，porcelain=isometric/porcelain-metal，aurora=isometric/aurora-optical。材质正向描述追加在原 styleBiblePrefix 之后、资产主题之前；material 缺省不追加任何字符。哈希旧路径原样保留，有 material 才在原字段序列尾追加域标签及材质值。模型不得把主题写成另一套画风。
4. 预览构建由独立脚本串行构建五个确定性项目，fixture 与脚本放在 scripts/admin-style-previews/，制品先写隔离临时目录，全部成功后供 web 构建复制至 admin-style-previews/{id}/{version}/。manifest 记录 id/version、模板指纹、素材类别及入口；发布构建验证目录完整及指纹一致。开发启动不触发付费构建，缺预览明确提示先运行预览构建命令。注册表与制品一起发布，禁止远程加载不受信任入口。
5. 保留两次介入：drafter 请求中传风格上下文帮助规划 admin 内容，输出后共享编排层再强制应用。不能用反复校验重试代替事前告知，不能只信提示词。iframe 首批仅 allow-scripts，不授予 allow-same-origin，预览测试需确认资源可加载且功能无存储依赖；若需额外权限，必须采用独立源设计，不直接扩大同源沙箱权限。
