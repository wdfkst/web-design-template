# 个性化后台生成设计

日期：2026-10-29。状态：完整设计已由用户确认，进入实施计划阶段（尚未开始实现）。基于当前 `worktree-modern-admin-generator` 的 1.0，不修改生成平台控制台的视觉。

## 1. 用户目标与已确认方向

生成个性化程度高、元素丰富、美观实用且适合快速二开的 Vue 3 后台。业务场景不受行业模板限制，页面、字段、工作台内容及图像应由用户需求驱动。

用户已确认 V2 柔光玻璃与轻拟态质感，并认可 V3 列表/详情/编辑和 V3.1 图标插画增强方向：柔和渐变光晕、磨砂叠层、细腻投影、业务图标及适量插画。原型里的项目记录、名字、文案、紫色与文件夹不是固定业务或品牌。

原型位于本地 `.superpowers/brainstorm/3028-1793261147/content/`，仅供视觉参考，未成为生成器代码；原型本地数据交互不能代替正式组件测试。

## 2. 本轮范围与明确不做

本轮交付：可配置的后台视觉体系；有限且可组合的列表、详情、表单和工作台变体；正常数据状态也能看见的业务插画；有数据依据的工作台模块；清晰的导出工程定制入口。

保留 Ant Design Vue、现有 CRUD 和导航，不推翻底座。不增加真实后端、权限认证系统、工作流引擎、跨实体关系模型、平台项目持久化、版本管理、局部重新生成、图形化编辑器或参考图上传。这些后续独立立项。不能将本轮描述成已经提供生产业务系统。

业务不限定不代表组件无限：支持范围由 schema 明确表达，超出能力给可理解的校验反馈，不生成无作用按钮冒充支持。

## 3. 视觉体系

以下参数结构属于执行者建议，尚非用户逐项指定。

为 admin experience 增加可选 presentation 配置，包含 appearance（plain/soft-glass）、decoration（minimal/balanced）、density（compact/comfortable）及 shell（sidebar/topbar）。旧 spec 未带配置时保持旧样式与结构；新后台草稿默认 soft-glass/balanced，需求明确要求克制时采用 plain/minimal。

颜色继续来自 theme.colorTokens，字体保留系统回退，不自动加载未知外部字体。模型选择语义参数与色板，不输出任意 CSS、HTML、阴影字符串或背景 URL。渐变颜色、透明度、阴影、模糊半径由受控模板和 tokens 派生，使用同一 palette 贯穿导航、组件及插画。

分层规则：
- 外层背景：柔光渐变，主色加辅助色，避免高频动画。
- 导航/欢迎区域：磨砂叠层和轻拟态边缘。
- 表格/表单：较实的背景和明确边界，不给文字施加 blur；不把可点击状态仅靠阴影表达。
- 插画：欢迎区或列表标题区域，侧栏少量点缀；窄屏装饰收缩或隐藏，不盖住内容。
- 控件：正常、悬停、焦点、禁用、错误状态明确，不能只有色差。

light/dark 各自派生材质参数；both 跟随系统并同步 Ant 算法和自定义 CSS，不只切换背景。正文对比度目标 4.5:1，装饰不可成为辨识按钮的唯一手段。无 backdrop-filter 时回退实色；减少动态效果设置生效。模糊限制在少量容器，不在每行或每个单元格重复使用。

## 4. 页面组织

首批采用有限变体，避免承诺所有可能布局：
- 列表：table / cards。两者消费同一集合、筛选、typed actions、编辑抽屉与分页；卡片指定标题、摘要字段，字段引用须校验。没有图片字段时不虚构图片。
- 详情：sections / aside。指定分组及字段；侧边摘要是同条记录的受控字段投影，不是另一份数据。
- 表单：single / grouped。复用现有表单校验、保存、返回行为；分组仅改变展示，不改变数据语义。此次不做分步表单、复杂联动或主从明细。
- 工作台：overview / focus。按模块列表组织主要区域和辅助区域，不固定行业名称。

缺省使用现有布局。新增布局参数只用于 admin 路径，不改变 marketing 页面。字段标签来自数据模型，页面标题与说明来自业务需求；空态、错误态、返回入口全部可用。长标题、无数据、较多列、未知记录 ID 必须有确定行为。

## 5. 业务工作台

模块仅包含首批四类：
1. summary：collection count，以及数值字段 sum；允许枚举或布尔字段等值过滤。
2. breakdown：按枚举或布尔字段分组计数，显示带标签的分布列表；本轮不新增图表库或伪造时间趋势。
3. records：集合的有限条记录，可按 date/number 字段排序、按枚举或布尔等值过滤；用于待处理、最近记录等。无合法日期字段时不得声称是“最新”。
4. shortcuts：仅指向已存在且允许导航的路由。

每个模块有稳定 id、标题和数据来源；引用集合、字段、操作、路由由 schema 校验。sum 不允许字符串字段，空集合返回明确零值或空态，不显示 NaN。过滤枚举值必须合法。上限为每页 8 个模块，records 每块最多显示 10 条；同一数据层修改后同步重算，不维护独立假统计。

不得虚构增长率、同比、会议、通知、活动日志或业务记录。模拟数据可以提供演示，但要明确模拟来源；“最近记录”不冒充审计日志。工作台记录点击详情必须存在同集合详情路由，否则只展示信息。

## 6. 图标与图片

操作图标使用受控 Ant Design 图标映射，扩展语义目录覆盖文档、日程、团队、媒体、任务等通用概念；不允许动态执行任意图标名或拼接任意 SVG。图标配文字，装饰图标 aria-hidden。

新增专用后台欢迎插画侧车区块，支持工作台和列表标题区域；保留 EmptyStatePanel 与 AuthPanel。页面最多一个欢迎插画和一个空态插画，auth 保留自身规则。此处明确替换旧“业务页最多一个 EmptyStatePanel”的限制，而不是绕过校验。

图片几何、宽高、透明背景和构图来自侧车；模型仍只能填内容 prompt/alt，不得手写尺寸。新增区块必须同时登记 draft 目录、derive、注册表、完整性校验及 admin codegen 资产消费，不得仅在 UI 中添加未绑定的占位图。

图片风格结合 theme palette 派生有效色板；styleBible 保留艺术风格与负面提示约束。只在 admin 新视觉配置路径采用同色源，避免改变旧营销任务。最终实际 prompt、内容哈希及请求记录必须使用同一有效输入，缓存不能串色。

不为每行生成图片，不扩大现有单任务资产上限。minimal 时省略欢迎装饰；没有资产时仍有完整布局，不因图片缺失显示破图。生成失败沿用现有失败语义，不偷偷用其他图冒充成功。

## 7. 生成与二开

沿用一次 draft 加校验反馈，不在本轮添加额外规划模型调用。drafter 先按需求选页面与模块，再选风格，不能机械地每个后台都生成相同首页。目录提示应列合法变体、模块、字段引用规则和已不支持的功能。

生成器继续拷模板、发射类型化配置/数据与页面包装。主题 tokens、页面配置、共享组件、数据 repository 分层。导出 README 按实际生成页面列出定制入口，解释何处换主题、调整列、修改表单和替换数据层，明确模拟数据刷新重置。

不承诺重新生成保留用户本地改码，也不为了未来编辑器构建复杂 patch 引擎；模块采用稳定语义 id 即可。

## 8. 兼容与成本

旧 spec 解析与旧后台、营销输出保持兼容。新增字段有明确缺省，未知字段继续拒绝。新 UI 布局不得修改集合存储或 existing typed action 的行为。

图片新增意味着潜在调用和耗时增加：默认欢迎插画最多一个/页，不保证所有页面都有图；遵守现有资产上限、缓存去重与请求可见性。此次不主动调用用户付费模型进行验收，真实调用需后续明确安排。

## 9. 验收

- 同一业务不同风格有材质、密度差异；不同业务需求有实际布局与模块差异，不仅换色换字。
- 至少三个差异明显的需求 fixture，用于测试而非限制行业。
- 列表/卡片→详情→编辑保存闭环，筛选、分页、空态、验证和批量操作不回退。
- 工作台统计来自同一集合；新增、修改、删除后同步变化；非法字段、枚举、路由、模块数和记录条数均被拒绝。
- 旧 spec、marketing、auth、旧 admin 输出回归，生成项目 vue-tsc 和 Vite 均通过。
- 图片侧车几何、资产实际使用、缓存色板变化、最终提示词快照一致性有测试。
- 1440/1024/390 宽度检查，页面不横向溢出（表格容器可滚动），明暗及 both 切换、键盘焦点、表单错误、长文案、无 blur 回退检查。
- 原型认可不替代正式实现截图与交互验证；无法完成的手验单列，不以测试通过冒充。

## 10. 可实施性检查后的执行者取舍

以下是执行者为消除接口歧义作出的设计建议，不代表用户逐项指定。独立检查已完成；现有代码缺少新能力的实现是本轮开发内容，本身不是需要用户决定的阻塞。

- 变体使用各 mode 内可选的 variant，非法组合拒绝。overview 按模块声明顺序排列，摘要优先形成紧凑概览，其余模块使用等宽网格；focus 显式指定一个 records 模块的 id 为主区域，其他模块为辅助区域，桌面主辅比例 2:1。focus 缺主模块或引用非 records 模块时拒绝；窄屏主区域在前、辅助区域在后，全部单列。
- 工作台保留旧 collections/shortcuts 结构作为兼容分支；新增 modules 分支，不允许与旧字段混用。旧输入不自动迁移，不受新模块数量限制；新输入使用 modules（1–8 个，页内 id 唯一）。集合型模块声明 collection，shortcuts 声明路由列表，不要求伪造 collection 来源。
- 新 presentation 路径的 both 在生成工程中监听 prefers-color-scheme，首次加载与系统变化时同步切换 Ant 算法及 CSS 材质；卸载清理监听，不提供额外主题选择持久化。无 presentation 的旧输入保留既有行为，包括旧 both 行为。插画仅生成一套，以原始 theme palette 为稳定色源，不随明暗切换重新生成或改变缓存键；两种材质均验证其可读性。
- presentation.density 显式值优先于 theme.spacing，仅覆盖后台控件与内容间距；缺省沿用 theme.spacing。compact 对应紧凑，comfortable 对应 normal；旧 relaxed 不被缺省覆盖。新草稿推荐 comfortable/sidebar，导航内容和业务数据不受密度影响。
- topbar 支持现有导航分组：叶项直接导航、分组以可键盘操作的下拉菜单显示子项；窄屏收进可展开菜单。sidebar 与 topbar 消费同一导航树，不额外限制业务导航为扁平结构。
- 区块校验按页面类型分支：list/workbench 允许至多一个欢迎区块和一个 EmptyStatePanel（总数最多 2）；其他非 auth 页面仍至多一个 EmptyStatePanel；auth 保持现有 AuthPanel 规则，不接纳欢迎区块。同类型重复拒绝。minimal 不得声明欢迎区块，校验反馈要求 draft 删除它，避免生成后再隐藏造成付费浪费。

## 11. 待确认的整体取舍

默认沿用已认可柔光方向，但保留 plain/minimal；本轮布局变体有界，暂不做分类树、看板、分步表单；工作台先做有数据依据的摘要/分布/记录/快捷入口，不先上复杂图表；先改善生成结果，平台内局部编辑与项目持久化后续处理。
